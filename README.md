# لمسة — Lamssa

نموذج أولي لإدارة عيادات التجميل بواجهة **عربية أولًا وباتجاه RTL**، مبني باستخدام
React وTypeScript وVite. الهدف منتج SaaS يخدم عيادات مستقلة متعددة؛ النسخة الحالية
واجهة محلية تجريبية لعيادة واحدة، ولا توفر تعدد العيادات فعليًا.

**لا تُدخل بيانات مرضى حقيقية.** جميع بيانات العرض وهمية، والنموذج غير جاهز للاستخدام
الطبي أو المالي الفعلي.

## التشغيل المحلي

تحتاج إلى Node.js وnpm. تم التحقق محليًا باستخدام Node.js `24.21.0` وnpm `11.19.0`؛
لا يحدد المشروع إصدارًا إلزاميًا في `engines` حتى الآن.

```bash
npm ci
npm run dev
```

افتح العنوان الذي يظهر في الطرفية، عادةً `http://localhost:5173`.
البناء يشغّل فحص TypeScript الصارم ثم ينتج ملفات الإنتاج في `dist`:

```bash
npm run build
npm run preview
```

لمعاينة محلية على الجهاز فقط، يمكن تقييد عنوان الاستماع؛ أوامر Vite الحالية تستخدم
`0.0.0.0` افتراضيًا:

```bash
npm run dev -- --host 127.0.0.1
npm run preview -- --host 127.0.0.1
```

لا توجد أوامر `test` أو `lint` أو إعدادات اختبارات حاليًا. React وReact DOM هما
اعتمادا التشغيل الوحيدان؛ الإصدارات المثبتة في ملف القفل: React `19.3.1`،
Vite `6.4.5`، TypeScript `5.9.3`، وإضافة React لـVite `4.7.0`.

## الوظائف الحالية

- لوحة تحكم لمواعيد اليوم وإجمالي المرضى والمنتظرين وجميع المبالغ المحصلة.
- إضافة مرضى ببيانات إدارية والبحث بالاسم أو الهاتف.
- إنشاء مواعيد لمريض موجود، والبحث وتسجيل الحضور لإضافته إلى الطابور.
- استدعاء مريض واحد إلى الغرفة وإنهاء زيارته وتحديث حالة موعده.
- إنشاء فواتير بوصف ومبلغ وحالة سداد، والبحث وتسجيل السداد.
- تخزين الحالة محليًا واستعادتها بعد إعادة التحميل؛ استعادة بيانات العرض بتأكيد المستخدم.
- تصميم عربي متجاوب، مع عرض الهاتف والوقت باتجاه LTR عند الحاجة.

التنقل بين الأقسام عبر حالة React داخل الصفحة؛ لا توجد مسارات URL أو مكتبة توجيه.
اسم العيادة والصورة الرمزية للعرض فقط، ولا يمثلان تسجيل دخول أو تبديل عيادات.

## التخزين والقيود

تُحفظ مصفوفات المرضى والمواعيد والطابور والفواتير معًا في `localStorage` تحت المفتاح
`lamssa-clinic-demo-v1`. بقي المفتاح وشكل البيانات كما هما. التخزين خاص بالمتصفح
وبنفس عنوان الموقع، بما يشمل البروتوكول والمضيف والمنفذ؛ تغييرها لا ينقل البيانات.
لا يوجد استيراد تلقائي إلى قاعدة بيانات، ولم تُحذف بيانات متصفح المستخدم في هذه الخطوة.

- لا يوجد backend أو قاعدة بيانات أو مصادقة أو صلاحيات أو عزل بين العيادات.
- بيانات المتصفح ليست مصدرًا موثوقًا أو محميًا للبيانات الطبية؛ لا يوجد سجل تدقيق أو
  نسخ احتياطية مُدارة أو سياسات احتفاظ أو موافقات أو حماية صور طبية.
- التحقق محدود بقيود النماذج؛ فحص التخزين يتحقق من وجود المصفوفات فقط. التخزين التالف
  يعود إلى بيانات العرض وقد تُكتب فوقه تلقائيًا بالسلوك الحالي؛ فشل الكتابة غير معالج.
- لا يوجد تزامن بين الأجهزة أو علامات التبويب. الطابور لغرفة واحدة ولا يضمن منع
  التكرار عند العمل المتزامن؛ لا يوجد منع لتعارض حجوزات الطبيب أو الغرفة.
- التاريخ اليومي ثابت منذ تحميل التطبيق، وترقيم الطابور يخلط اليوم المحلي مع UTC؛
  قائمة الانتظار لا تُرشّح باليوم. العملة ثابتة بالريال اليمني.
- أرقام الفواتير المعروضة مشتقة من ترتيب النتائج وتتغير عند البحث؛ السداد قيمة منطقية
  دون سجل دفعات أو سداد جزئي أو استرجاع أو ضرائب.
- خط Cairo يُحمّل من Google Fonts مع خطوط بديلة محلية.

## البنية المستهدفة وخطة الانتقال

الاختيار المقترح مستودع موحد تدريجي باستخدام npm workspaces:

```text
apps/web          # واجهة React + Vite الحالية بعد نقلها في خطوة مستقلة
apps/api          # مستقبلًا: NestJS REST API
packages/shared   # مستقبلًا: أنواع النقل وعقود التحقق المشتركة
docs              # قرارات البنية وخطة التنفيذ
```

الخادم المستهدف NestJS مع PostgreSQL وPrisma، في تطبيق خلفي مقسّم إلى وحدات.
تشارك العيادات قاعدة بيانات واحدة، مع `clinicId` على السجلات التابعة للعيادة،
وسياق عضوية وصلاحيات يتحقق منه الخادم، ومفاتيح علاقات وقيود وفهارس تشمل العيادة.
تُخطط حماية إضافية بسياسات PostgreSQL RLS قبل استخدام بيانات حقيقية.
تقلل القاعدة المشتركة العبء التشغيلي لكنها تتطلب اختبارات صارمة لمنع تسرب البيانات.

هذه المجلدات والخدمات وقاعدة البيانات **لم تُنشأ بعد**. الخطوة التالية المقترحة 1.2
هي نقل الواجهة إلى `apps/web` وتأسيس workspaces مع إبقاء أوامر الجذر وسلوك التخزين.
يليها تأسيس API وقاعدة البيانات والمصادقة والعزل، ثم نقل المرضى والمواعيد والطابور
والفوترة تدريجيًا إلى الخادم.
