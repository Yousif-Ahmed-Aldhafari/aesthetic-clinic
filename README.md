# لمسة — نظام إدارة عيادة تجميل (MVP Prototype)

واجهة أولية تفاعلية **باللغة العربية واتجاه RTL**، قابلة للتشغيل محليًا، لتجربة سير العمل الأساسي في عيادة تجميل.

## تشغيل المشروع

```bash
npm install
npm run dev
```

افتح العنوان الذي يظهر لك في الطرفية (عادةً `http://localhost:5173`).

للتأكد من صحة البناء:

```bash
npm run build
```

## ما الذي يعمل الآن؟

- لوحة تحكم بمؤشرات أساسية.
- إضافة مرضى والبحث عنهم.
- حجز مواعيد وتسجيل حضور المريض.
- طابور انتظار برقم دور: انتظار ← داخل الغرفة ← انتهى.
- إصدار فواتير بسيطة وتسجيل سدادها.
- حفظ البيانات في `localStorage` داخل المتصفح نفسه وإعادة ضبط بيانات العرض.
- تجربة واجهة عربية متجاوبة مع الهاتف والكمبيوتر.

## تنبيهات مهمة

- **هذا نموذج أولي (frontend prototype)، وليس نظامًا طبيًا أو ماليًا جاهزًا للاستخدام الفعلي.** جميع أسماء المرضى والأرقام الموجودة عند التشغيل بيانات **وهمية**.
- **لا تُدخل بيانات مرضى حقيقية**: لا يوجد تسجيل دخول أو قاعدة بيانات خلفية، ولا تشفير خادمي، ولا سجل تدقيق أو نسخ احتياطية أو فصل بيانات العيادات.
- حفظ البيانات محليًا في المتصفح فقط؛ ليست مشتركة بين أجهزة الاستقبال والطبيب ولا تدعم تزامنًا لحظيًا.
- التاريخ والعملة والنصوص قابلة للضبط عندما تتحدد منطقة التشغيل والمتطلبات.
- وظيفة الطابور نموذج مبسط لغرفة واحدة. دعم عدة أطباء/غرف وحجز الموارد ومنع تعارض المواعيد ضمن المرحلة التالية.
- لم تُبنَ بعد السجلات الطبية أو الموافقات أو الصور أو الجرد أو الصلاحيات أو التقارير المتقدمة أو الضرائب.

## مراحل التطوير التالية (المقترحة)

1. تأسيس backend وقاعدة بيانات PostgreSQL وواجهات API، مع نموذج بيانات متعدد العيادات وفصل الوصول على الخادم.
2. تسجيل الدخول والصلاحيات (مدير النظام، مدير العيادة، استقبال، طبيب، محاسب)، وسجل التدقيق.
3. دورة الزيارة: خدمة/طبيب/غرفة/موعد/حضور/انتظار/دخول/إنهاء، ومنع الحجز المزدوج.
4. الفوترة الفعلية والمدفوعات والخصومات والإرجاعات وإعدادات العملة والضرائب.
5. الملف الطبي والموافقات والصور الحساسة وسياسات الاحتفاظ، بعد مراجعة المتطلبات التنظيمية المحلية.
6. الجرد، الحملات، الإشعارات، التقارير، والاشتراكات SaaS.

## تفاصيل تقنية

- Vite + React + TypeScript
- CSS مخصص، `dir="rtl"`
- لا يوجد backend بعد.
